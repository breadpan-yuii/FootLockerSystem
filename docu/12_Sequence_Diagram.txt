12 - SEQUENCE DIAGRAMS (SPLIT IN TWO) - STEP BY STEP + INPUTS
========================================================================
GOAL: Show the message order for "add to cart" (04a) and "checkout" (04b)
as TWO focused figures - split because one combined figure is too tall
to stay legible. Matches app/Http/Controllers/CartController.php ::store
and app/Http/Controllers/CheckoutController.php ::index + ::store.

------------------------------------------------------------------------
(A) RECOMMENDED TOOLS
------------------------------------------------------------------------
- plantuml.com (paste part (E) blocks - fastest).
- draw.io / diagrams.net (UML sequence shapes).
- Lucidchart, StarUML.

------------------------------------------------------------------------
(B) FIGURE 04a - ADD TO CART (CartController::store - POST /cart)
------------------------------------------------------------------------
LIFELINES left to right: Customer, Browser, CartController,
Cart / CartItem (Model), Database. Activation bar on CartController.
 1. Customer -> Browser : submit "Add to Cart"
 2. Browser -> CartController : POST /cart (product_id, product_variant_id?, qty 1-20)
 3. CartController -> CartController : validate input
 4. CartController -> Database : find active product + variant (variant must
    belong to product; 404 otherwise)
 5. CartController -> CartController : check available = variant.stock ??
    product.stock >= qty (else back() with "not enough stock")
 6. CartController -> Cart : firstOrCreate cart for user
 7. alt item already in cart
       Cart/CartItem -> Database : UPDATE cart_items increment quantity
    else new item
       Cart/CartItem -> Database : INSERT cart_items
 8. CartController -> Browser : redirect GET /cart (success)
 9. Browser -> Customer : show cart

------------------------------------------------------------------------
(C) FIGURE 04b - CHECKOUT (CheckoutController::store - POST /checkout,
in DB::transaction)
------------------------------------------------------------------------
LIFELINES left to right: Customer, Browser, CheckoutController,
Order / OrderItem (Model), Database. Activation bars on
CheckoutController and Order/OrderItem. Loop frame "for each cart item"
covers ONLY the per-item messages (create item, insert, decrement).
 1. Customer -> Browser : click "Place Order"
 2. Browser -> CheckoutController : POST /checkout (full_name, phone, address,
    payment_method in {Cash on Delivery, GCash, Bank Transfer}, notes?)
 3. CheckoutController -> CheckoutController : validate input
 4. CheckoutController -> Database : load cart items (guard: empty ->
    redirect GET /cart "bag is empty")
 5. CheckoutController -> CheckoutController : BEGIN transaction; compute
    subtotal = sum(display_price x qty); shipping = subtotal>=3000 ? 0 : 150
 6. CheckoutController -> Order : create order (status=pending)
 7. Order -> Database : INSERT orders (FL-XXXXXXXX uppercase random 8,
    subtotal/shipping/total/status/order_date/address/payment)
 8. loop each cart item
       CheckoutController -> OrderItem : create order item
       OrderItem -> Database : INSERT order_items (product/variant/qty/
       price/subtotal snapshot)
       CheckoutController -> Database : decrement variant stock (if variant)
       + decrement product stock
    end
 9. CheckoutController -> Database : DELETE cart_items (clear cart)
10. CheckoutController -> CheckoutController : COMMIT transaction
11. CheckoutController -> Browser : redirect GET /my-orders/{order} (success)
12. Browser -> Customer : show order number

Admin continuation (optional text, not drawn):
    Admin -> AdminOrderController : PATCH /admin/orders/{order}/status
    AdminOrderController -> Database : UPDATE orders.status
    (pending->confirmed->preparing->completed, or cancelled)

------------------------------------------------------------------------
(D) STEP-BY-STEP DRAWING INSTRUCTIONS (proper Sequence procedure)
------------------------------------------------------------------------
1. Per figure: draw participant boxes across the top ONLY for lifelines
   that exchange messages (04a: 5, 04b: 5 - drop unused participants).
2. Drop a dashed lifeline from each box to the bottom of the figure.
3. Add thin activation bars over each controller/model while it handles
   messages.
4. Draw messages strictly top-to-bottom in numbered order: solid line +
   filled arrowhead for calls, dashed line + open arrowhead for
   returns/redirects. Label every arrow above the line.
5. 04a: wrap the insert/increment pair in an alt/else frame.
   04b: wrap ONLY the per-item messages in a loop frame
   ("loop: for each cart item"); DELETE cart_items and COMMIT stay
   OUTSIDE the loop - they run once.
6. Never let an arrow cross a lifeline it does not target (message lines
   crossing uninvolved lifelines horizontally is normal UML; lines must
   not pass through participant boxes or activation bars of others).

(E) PLANTUML SOURCES (one block per figure)
------------------------------------------------------------------------
Figure 04a - Add to Cart:
@startuml
autonumber
actor Customer
participant Browser
participant "CartController" as CC
participant "Cart / CartItem" as Cart
database "Database" as DB
Customer -> Browser : submit "Add to Cart"
Browser -> CC : POST /cart (product_id, variant_id?, qty)
activate CC
CC -> CC : validate input
CC -> DB : find active product + variant
CC -> CC : check stock >= qty
CC -> Cart : firstOrCreate cart
alt item already in cart
  Cart -> DB : UPDATE increment quantity
else new item
  Cart -> DB : INSERT cart_items
end
CC --> Browser : redirect GET /cart (success)
deactivate CC
Browser --> Customer : show cart
@enduml

Figure 04b - Checkout:
@startuml
autonumber
actor Customer
participant Browser
participant "CheckoutController" as CoC
participant "Order / OrderItem" as Ord
database "Database" as DB
Customer -> Browser : click "Place Order"
Browser -> CoC : POST /checkout (delivery + payment)
activate CoC
CoC -> CoC : validate input
CoC -> DB : load cart items (guard: empty -> /cart)
CoC -> CoC : BEGIN + compute subtotal + shipping\n(subtotal>=3000 ? 0 : 150)
CoC -> Ord : create order (status = pending)
Ord -> DB : INSERT orders (FL-XXXXXXXX)
loop for each cart item
  CoC -> Ord : create order item
  Ord -> DB : INSERT order_items (price snapshot)
  CoC -> DB : decrement variant + product stock
end
CoC -> DB : DELETE cart_items
CoC -> CoC : COMMIT transaction
CoC --> Browser : redirect GET /my-orders/{order}
deactivate CoC
Browser --> Customer : show order number
@enduml
