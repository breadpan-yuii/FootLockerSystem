PROBLEMS AND SOLUTIONS

1. [CONFIRM] Product images were missing and looked inconsistent across
the catalog. We sourced real product images, stored them under
public/images/products (and brands/categories), and kept only the
relative path in the database, so the admin can change an image without
touching any code.

2. [CONFIRM] A product can have many sizes and colors, but a single
stock column was not enough. We added a product_variants table (size,
color, SKU, stock) and a product_images table, giving one-to-many
relationships from products.

3. [CONFIRM] A customer could add more items than the available stock.
In CartController::store the system now validates the requested
quantity against the selected variant (or product) stock and returns an
error message when stock is insufficient.

4. [CONFIRM] Prices in old orders changed when the admin edited a
product. We store a price snapshot (price and subtotal) inside
order_items at checkout time, so historical orders are unaffected by
later price changes.

5. [CONFIRM] Creating an order could leave the database in an incomplete
state (an order without items) if something failed midway. We wrapped
the checkout logic in a database transaction (DB::transaction), so
either everything is saved or nothing is.

6. [CONFIRM] Shipping-fee rules had to apply automatically. We
implemented the rule "free shipping when the subtotal reaches PHP
3,000, otherwise PHP 150" inside checkout.

7. [CONFIRM] Order numbers had to be unique and easy to share. We
generate each number in the format FL-XXXXXXXX (FL plus eight random
uppercase characters) backed by a UNIQUE constraint.

8. [CONFIRM] Some pages were reachable by the wrong users. We protected
customer pages with authentication middleware, restricted the admin
area with a role check (EnsureUserIsAdmin plus the "admin" route
middleware), and added ownership checks so a customer only ever sees
their own cart and orders (403 otherwise).

9. [CONFIRM] Styling differed between pages and looked inconsistent. We
adopted a single storefront layout with shared navigation and footer
and a consistent Tailwind-based design system (cards, buttons,
headings).

10. [CONFIRM] Built CSS did not appear after edits. We ran "npm run
build" to regenerate the compiled assets in public/build, since assets
are served from the build output.
