========================================================================
10a - USE CASE DIAGRAM - GUEST (FIGURE 02a) - STEP BY STEP + INPUTS
========================================================================
GOAL: A proper UML use case diagram for the GUEST actor (not logged in)
of the Foot Locker PH system. Actor OUTSIDE the system boundary; use
cases as ellipses INSIDE. Plain associations only (no arrowheads).

SOURCE OF TRUTH (verified): routes/web.php lines 18-25 (public catalog +
public order tracking) and routes/auth.php lines 14-35 (guest auth:
register, login, forgot/reset password).

SCOPE NOTE: Login/Logout/Password-reset ARE modeled here as real use
cases (they are guest goals), NOT hidden as preconditions. Email
verification is deliberately EXCLUDED: the routes exist (auth.php 39-47)
but the User model does not implement MustVerifyEmail and no route uses
the "verified" middleware, so the flow never triggers in the real system.

(B) INPUTS - EXACTLY WHAT TO DRAW (FIGURE 02a)
------------------------------------------------------------------------
ACTOR (stick figure, LEFT of the rectangle):
    Guest  - a person who is not logged in.
SUBJECT (rectangle, label at top):
    Foot Locker PH System
ELLIPSES (one per user goal - 6 total):
    [ ] UC1  Browse & Search Products
             GET / (home), GET /shop, GET /search?q=, GET /category/{category},
             GET /brand/{brand}   [web.php 18-22; ShopController]
    [ ] UC2  View Product Details
             GET /product/{product} (active products only, + related)
             [web.php 23; ShopController@show]
    [ ] UC3  Track Order  (PUBLIC - no login required)
             GET + POST /track-order by order number
             [web.php 24-25; OrderController@trackForm/track]
    [ ] UC4  Register Account
             GET + POST /register  [auth.php 15-18]
    [ ] UC16 Log In  (NEW id)
             GET + POST /login  [auth.php 20-23]
    [ ] UC17 Recover Forgotten Password  (NEW id)
             GET + POST /forgot-password, GET /reset-password/{token},
             POST /reset-password  [auth.php 25-35]
RELATIONSHIPS between use cases:
    NONE. These six goals are independent; there is no genuinely shared
    mandatory behavior (no «include») and no optional overlay (no
    «extend»). Do NOT add a "Login includes ..." arrow - login is a
    separate goal here, and the two password flows are distinct goals.
ASSOCIATIONS (plain lines, no arrowhead):
    Guest --- UC1, Guest --- UC2, Guest --- UC3,
    Guest --- UC4, Guest --- UC16, Guest --- UC17

------------------------------------------------------------------------
(C) STEP-BY-STEP DRAWING INSTRUCTIONS (proper use case procedure)
------------------------------------------------------------------------
1. Draw ONE large rectangle with "Foot Locker PH System" in the top-left
   (or centered at the top). This is the SUBJECT / system boundary.
2. Draw ONE stick figure to the LEFT of the rectangle, labeled "Guest".
   Actors must be OUTSIDE the boundary.
3. Place the 6 use cases as ELLIPSES inside the rectangle, in UC order
   (UC1, UC2, UC3, UC4, UC16, UC17), spaced so lines do not cross.
4. Connect the actor to each ellipse with a PLAIN solid line and NO
   arrowhead (association = communication).
5. Do NOT draw include/extend between these use cases (see section B).
6. Do NOT draw actor-to-actor lines and do NOT add a second actor.
7. Verify every ellipse against the cited route before export.

------------------------------------------------------------------------
(D) PLANTUML SOURCE (paste into plantuml.com / kroki.io)
------------------------------------------------------------------------
@startuml
left to right direction
skinparam dpi 300
skinparam shadowing false
skinparam nodesep 12
skinparam ranksep 40
skinparam padding 4
skinparam actorStyle stick
skinparam defaultFontName SansSerif
skinparam usecase {
  BackgroundColor White
  BorderColor Black
  ArrowColor Black
}
skinparam rectangle {
  BackgroundColor White
  BorderColor Black
}

actor Guest

rectangle "Foot Locker PH System" {
  usecase "UC1 Browse & Search Products" as UC1
  usecase "UC2 View Product Details" as UC2
  usecase "UC3 Track Order" as UC3
  usecase "UC4 Register Account" as UC4
  usecase "UC16 Log In" as UC16
  usecase "UC17 Recover Forgotten Password" as UC17
}

Guest -- UC1
Guest -- UC2
Guest -- UC3
Guest -- UC4
Guest -- UC16
Guest -- UC17
@enduml
