========================================================================
09 - FUNCTIONAL DECOMPOSITION DIAGRAM (FDD) - STEP BY STEP + INPUTS
========================================================================
GOAL: Show how the Foot Locker PH system is broken into subsystems and
modules. (Derived from routes/web.php.)

SOURCE: routes/web.php (lines 18-68) + routes/auth.php.
Every leaf below maps to a real route. No invented modules.

------------------------------------------------------------------------
(A) RECOMMENDED TOOLS
------------------------------------------------------------------------
- draw.io / diagrams.net (free) -> hierarchical boxes.
- Lucidchart, Canva, or even PowerPoint SmartArt (hierarchy).

------------------------------------------------------------------------
(B) INPUT TREE - EXACTLY WHAT TO DRAW
------------------------------------------------------------------------
LEVEL 0 (root):
    FOOT LOCKER PH SYSTEM

LEVEL 1 (two subsystems, from the two route groups):
    1.0 Customer / Public Website  (public routes + auth group)
    2.0 Admin / Owner Website      (auth+admin group, prefix /admin)

LEVEL 2 (one box per route group - no Level 3, keeps lines uncrossed):

1.0 Customer / Public Website
    1.1 Home               (GET /)
    1.2 Shop               (GET /shop, GET /search?q=, GET /category/{category},
                            GET /brand/{brand} - search/filter/sort by
                            brand, category, gender, price)
    1.3 Product Details    (GET /product/{product}, active only + related)
    1.4 Shopping Cart      (GET /cart, POST /cart, PATCH /cart/{cartItem},
                            DELETE /cart/{cartItem} - auth)
    1.5 Checkout           (GET /checkout, POST /checkout - auth)
    1.6 Order Tracking     (GET /track-order, POST /track-order - PUBLIC)
    1.7 Customer Account   (GET /my-orders, GET /my-orders/{order},
                            GET /wishlist, POST /wishlist/{product},
                            GET/PATCH/DELETE /profile, POST /logout - auth)

2.0 Admin / Owner Website (all under /admin, auth + admin middleware)
    2.1 Dashboard          (GET /admin)
    2.2 Manage Products    (resource /admin/products - full CRUD)
    2.3 Manage Categories  (resource /admin/categories except show)
    2.4 Manage Brands      (resource /admin/brands except show)
    2.5 Manage Customers   (GET /admin/customers, GET /admin/customers/{customer})
    2.6 Manage Orders      (GET /admin/orders, GET /admin/orders/{order},
                            PATCH /admin/orders/{order}/status)

NOTE: Auth screens (GET/POST /register, GET/POST /login) are entry points,
not separate FDD leaves - they gate 1.4/1.5/1.7 and 2.0. The /dashboard
redirect (routes/web.php line 47) only forwards admins to 2.1 and
customers to 1.7, so it is not its own box.

------------------------------------------------------------------------
(C) STEP-BY-STEP DRAWING INSTRUCTIONS (proper FDD procedure)
------------------------------------------------------------------------
1. Draw a single root rectangle at the top: "FOOT LOCKER PH SYSTEM".
2. Draw one horizontal bus below it with exactly two orthogonal drops.
3. At the drop ends draw the two Level-1 boxes (1.0 left, 2.0 right).
   Same box style, same size, vertically aligned.
4. Decomposition axis (one per level): Level 1 splits by route group
   (public+auth group vs auth+admin group); Level 2 splits into modules,
   one per route cluster. Keep this single axis - do not mix other
   criteria into the same level.
5. Under each subsystem draw ONE horizontal bus per row (comb/bracket
   style). Row 1 hangs directly off the bus. Row 2 hangs off its own bus,
   which is fed by ONE vertical drop taken from the END of the row-1 bus
   and stepped down through a gap between row-1 boxes - never through a
   box, never around the outside as a frame.
6. Connect with right-angle (orthogonal) connectors only. Never draw
   diagonal lines and never route a connector through another box.
7. Number every box (1.0, 1.1 ... 2.6) and keep numbers STABLE once cited.
   Enforce the two contracts: 100% RULE (children exhaust the parent -
   every route in routes/web.php + auth.php lives in exactly one leaf)
   and SINGLE PARENT (each leaf has exactly one incoming edge).
7. Keep boxes aligned in rows, equal style throughout, white fill with a
   neutral outline. Verify each leaf against routes/web.php before export.
