========================================================================
10 - USE CASE DIAGRAM - STEP BY STEP + INPUTS
========================================================================
GOAL: Show the actors and the functions (use cases) they perform.

------------------------------------------------------------------------
(A) RECOMMENDED TOOLS
------------------------------------------------------------------------
- draw.io / diagrams.net (use the UML "actor" and "ellipse" shapes).
- Lucidchart, StarUML, or plantuml.com (paste part (D)).

------------------------------------------------------------------------
(B) INPUTS - EXACTLY WHAT TO DRAW
------------------------------------------------------------------------
ACTORS (stick figures, placed OUTSIDE the system boundary):
  - Guest        (not logged in)
  - Customer     (logged in, role = customer)
  - Admin        (logged in, role = admin)

SYSTEM BOUNDARY: a large rectangle labeled "Foot Locker PH System".

USE CASES (ellipses INSIDE the boundary):
  Guest / Customer:
    UC1  Browse Products
    UC2  Search / Filter Products
    UC3  View Product Details
    UC4  Register Account
    UC5  Login
  Customer only (after login):
    UC6  Manage Cart
    UC7  Checkout
    UC8  Place Order
    UC9  Track Order
    UC10 View My Orders
    UC11 Manage Wishlist
    UC12 Manage Profile
    UC13 Logout
  Admin only:
    UC14 View Dashboard
    UC15 Manage Products (CRUD)
    UC16 Manage Categories (CRUD)
    UC17 Manage Brands (CRUD)
    UC18 View Customers
    UC19 Manage Orders
    UC20 Update Order Status

RELATIONSHIPS:
  - Guest -> UC1..UC5 (plain association lines; no arrowheads)
  - Customer -> UC6..UC13 (plain association lines; no arrowheads)
  - Admin -> UC14..UC20 (plain association lines; no arrowheads)
  - Do not add include/extend relationships unless the team documents a
    genuine optional or reusable behavior. The core implementation is
    represented clearly by actor-to-use-case associations.

------------------------------------------------------------------------
(C) STEP-BY-STEP DRAWING INSTRUCTIONS
------------------------------------------------------------------------
1. Draw the big system boundary rectangle, write the system name at top.
2. Place "Admin" on the right side, "Customer" and "Guest" on the left.
 3. Add the use-case ellipses inside the boundary, grouped by actor.
 4. Connect each actor to its use cases with plain association lines.
 5. Keep Guest use cases in the upper-left group, Customer use cases in
    the lower-middle group, and Admin use cases on the right. This avoids
    connectors crossing other use-case ellipses.
 6. Do not use arrowheads on ordinary actor associations.
 7. Verify each use case maps to a real route (see routes/web.php).

------------------------------------------------------------------------

------------------------------------------------------------------------
