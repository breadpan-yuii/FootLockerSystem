========================================================================
10c - USE CASE DIAGRAM - ADMIN (FIGURE 02c) - STEP BY STEP + INPUTS
========================================================================
GOAL: A proper UML use case diagram for the ADMIN actor (logged in,
role = admin, gated by the "admin" middleware) of Foot Locker PH. Actor
OUTSIDE the boundary; use cases as ellipses INSIDE. Plain associations
plus one «include» and one «extend».

SOURCE OF TRUTH (verified): routes/web.php 47-68 (admin group, prefix
/admin, middleware auth+admin), 42-44 + auth.php 55/57 (profile, password
change, logout), app/Http/Middleware/EnsureUserIsAdmin.php, and
resources/views/admin/orders/show.blade.php:43 (status form lives on the
order-detail page).

INHERITANCE NOTE: The Admin shares the same auth group as customers, so
an Admin can ALSO perform every Customer use case (browse, cart,
checkout, my-orders, wishlist) - cart/checkout routes require only
"auth", not a customer role (web.php 27). Those are documented in
10b_Use_Case_Customer.txt and are NOT repeated here to keep this figure
readable; this figure shows the ADMIN-specific panel goals plus the
session/account goals the admin actor triggers directly.

(B) INPUTS - EXACTLY WHAT TO DRAW (FIGURE 02c)
------------------------------------------------------------------------
ACTOR (stick figure, RIGHT):  Admin (logged in + role = admin)
SUBJECT (rectangle):          Foot Locker PH System
ELLIPSES (12 total):
    [ ] UC16 Log In        GET+POST /login (shared form) [auth.php 20-23]
    [ ] UC10 View Dashboard GET /admin - revenue, order/status counts,
                            top products  [web.php 56]
    [ ] UC11 Manage Products resource /admin/products full CRUD incl.
                            variants + image gallery  [web.php 58]
    [ ] UC12 Manage Categories resource /admin/categories (except show)
                            [web.php 59]
    [ ] UC13 Manage Brands  resource /admin/brands (except show) [web.php 60]
    [ ] UC14 View Customers GET /admin/customers (+ /{customer})
                            [web.php 62-63]
    [ ] UC15 View Orders    GET /admin/orders (filter by status, search)
                            [web.php 65]
    [ ] UC20 View Order Details GET /admin/orders/{order} (NEW id)
                            [web.php 66]
    [ ] UC21 Update Order Status PATCH /admin/orders/{order}/status
                            pending->confirmed->preparing->completed
                            (or cancelled) (NEW id) [web.php 67]
    [ ] UC9  Manage Profile  PATCH /profile; PUT /password [web.php 42-43]
    [ ] UC18 Log Out         POST /logout (NEW id) [auth.php 57]
    [ ] UC19 Delete Account  DELETE /profile (extending case) [web.php 44]
RELATIONSHIPS between use cases (TWO are genuine):
    [ ] UC21 Update Order Status  «include»  UC20 View Order Details
        - DASHED arrow from UC21 TO UC20, labeled «include».
        - Why include: the status form is rendered ON the order-detail
          page (resources/views/admin/orders/show.blade.php:43), so
          viewing the details ALWAYS happens as part of updating status.
    [ ] UC19 Delete Account  «extend»  UC9 Manage Profile
        - DASHED arrow from UC19 TO UC9, labeled «extend».
        - Why extend: deleting is optional and password-confirmed; UC9 is
          complete without it.
    Do NOT add "includes Log In" arrows: authentication is a precondition.
ASSOCIATIONS (plain lines, no arrowhead):
    Admin --- UC16, UC10, UC11, UC12, UC13, UC14, UC15, UC9, UC18
    (UC20 is reached through UC21 via «include»; UC19 through UC9 via
     «extend» - do not draw a direct actor line to those two.)

(C) STEP-BY-STEP DRAWING INSTRUCTIONS
------------------------------------------------------------------------
1. Draw the rectangle "Foot Locker PH System" (the subject).
2. Draw ONE stick figure to the RIGHT, labeled "Admin".
3. Place the 12 ellipses inside the rectangle in UC order
   (UC16, UC10, UC11, UC12, UC13, UC14, UC15, UC20, UC21, UC9, UC18, UC19).
4. Connect the actor with PLAIN solid lines to UC16, UC10, UC11, UC12,
   UC13, UC14, UC15, UC9, UC18 (NO arrowheads).
5. Draw the dashed «include» arrow from UC21 to UC20, and the dashed
   «extend» arrow from UC19 to UC9.
6. No actor-to-actor lines; no generalization between actors.
7. Verify every ellipse against the cited route.
