11 - ACTIVITY DIAGRAM - STEP BY STEP + INPUTS
========================================================================
GOAL: Show the add-to-cart + checkout process flow (matches the actual code:
app/Http/Controllers/CartController.php ::store and
app/Http/Controllers/CheckoutController.php ::index + ::store).

SOURCE: CartController lines 22-63 (validate, active check, variant check,
stock guard, firstOrCreate, increment-or-create, redirect cart.index);
CheckoutController lines 14-23 (empty-cart guard) and 25-85 (validate
full_name/phone/address/payment_method in {Cash on Delivery,GCash,
Bank Transfer}/notes, empty-cart guard, DB::transaction, subtotal =
sum(display_price*qty), shipping = subtotal>=3000 ? 0 : 150, Order::create
status=pending order_number=FL-XXXXXXXX, items with price snapshot,
decrement variant stock if present + product stock, DELETE cart_items,
redirect orders.show).

------------------------------------------------------------------------
(A) RECOMMENDED TOOLS
------------------------------------------------------------------------
- draw.io / diagrams.net (initial/final nodes, action rectangles, diamonds).
- Lucidchart, StarUML, or plantuml.com (paste part (D)).

------------------------------------------------------------------------
(B) INPUTS - NODES AND FLOW (in order, top to bottom)
------------------------------------------------------------------------
PRECONDITION (note on canvas): logged-in customer - every step from A2
on runs behind the auth middleware (login); guests are redirected.
INITIAL NODE (filled circle)
 A1. Customer browses shop          (GET /shop, /search, /category, /brand)
 A2. Customer adds item to cart     (POST /cart: product_id required,
                                     product_variant_id nullable, qty 1-20)
     DECISION D1: "Enough stock?"   (available = variant.stock ?? product.stock)
        - [No]  -> E1 Show error "not enough stock" -> MERGE M1 back to A2
                    (customer retries; code does back() - NO termination)
        - [Yes] -> A3
 A3. Customer opens cart            (GET /cart)
 A4. Customer opens checkout        (GET /checkout)
     DECISION D2: "Cart empty?"
        - [Yes] -> E2 Return to cart with "bag is empty" -> back to A3
        - [No]  -> A5
 A5. Customer fills delivery details (full_name, phone, address, notes)
 A6. Customer selects payment method (Cash on Delivery / GCash / Bank Transfer)
 A7. System validates checkout form (same rules as above)
 A8. System computes subtotal       (sum of display_price x qty, in transaction)
     DECISION D3: "Subtotal >= PHP 3,000?"
        - [Yes] -> B1 Shipping = PHP 0
        - [No]  -> B2 Shipping = PHP 150
     MERGE M2: B1 + B2 rejoin (one merge diamond, no guard)
 A9.  System creates Order          (status=pending, FL-XXXXXXXX, inside
                                     DB::transaction with totals)
 A10. System creates Order Items    (product/variant/qty/price/subtotal snapshot)
 A11. System decrements stock       (variant stock if variant exists AND
                                     product stock, per item)
 A12. System clears the cart        (DELETE cart_items, same transaction)
 A13. System shows order number     (redirect GET /my-orders/{order})
FINAL NODE (filled circle with ring)

Admin continuation (off-diagram note, not a node):
  pending -> confirmed -> preparing -> completed (or cancelled),
  via PATCH /admin/orders/{order}/status.

DECISION DIAMONDS: D1 (stock), D2 (empty cart), D3 (free shipping).
MERGE DIAMONDS: M1 (stock-error retry into A2), M2 (shipping paths into A9).
Every branch arrow carries its guard in brackets: [No], [Yes].

------------------------------------------------------------------------
(C) STEP-BY-STEP DRAWING INSTRUCTIONS (proper Activity procedure)
------------------------------------------------------------------------
1. Draw the INITIAL node (filled circle) at the top center.
2. Add action rectangles A1 -> A2 vertically, one arrow straight down.
3. Add decision diamond D1 "Enough stock?". Left arrow [No] to E1, then a
   merge path M1 routing OUTSIDE the main column back up into A2. Down
   arrow [Yes] to A3. Label every branch; never leave a guard off.
4. Add A3 -> A4, then diamond D2 "Cart empty?". Left arrow [Yes] to E2,
   routed back up into A3 outside the column. Down arrow [No] to A5.
5. Add A5 -> A6 -> A7 -> A8 straight down the center column.
6. Add diamond D3 "Subtotal >= PHP 3,000?". Right arrow [Yes] to B1,
   left arrow [No] to B2; both arms drop down and rejoin at merge
   diamond M2 on the center line, then one arrow into A9.
7. Add A9 -> A10 -> A11 -> A12 -> A13 straight down, then the FINAL node
   (ringed circle). All main-flow arrows point down; retry arrows point
   up along the outer margins so no line crosses a shape.
8. Use standard notation only: filled-circle start, ringed end, rectangles
   for actions, diamonds for decisions AND merges, arrows for flows.
